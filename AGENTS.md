+# Repository guidance
+
+## Site
+
+This repository contains a personal portfolio website. Build a clear landing page that introduces the portfolio owner and guides visitors to their work and contact details. Include these pages or sections as the project grows:
+
+- Home: a brief introduction and featured work.
+- Projects: selected projects with concise descriptions and links.
+- About: background, skills, and experience.
+- Contact: a direct way to get in touch.
+
+Keep the navigation and content aligned with the pages that actually exist. Update this file when the site purpose or structure changes.
+
+## Design
+
+Use a clean, readable, understated portfolio style with generous whitespace and clear visual hierarchy. Prefer a light neutral background, dark text, and one restrained accent color. Use system sans-serif fonts unless the project establishes a different typeface. Keep layouts responsive and accessible, with visible keyboard focus and sufficient color contrast. Update this section when the design changes.
+
+## Implementation rules
+
+- Use plain HTML, CSS, and JavaScript only; do not add frameworks or build tools.
+- Use relative paths for local assets and links so the site works from the repository.
+- Keep markup semantic, CSS organized, and JavaScript focused on interactions that need it.
+
+## Git workflow
+
+- After each completed task, create a commit with a clear, task-specific message.
+- Push the commit to the configured GitHub remote.
+- Do not include unrelated changes in a task commit.
